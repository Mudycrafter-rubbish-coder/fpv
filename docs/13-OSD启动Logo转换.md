# 13 · OSD 启动 Logo 转换（288×72 BMP）

这个工具把任意图片转成 MAX7456 / OSD 启动 Logo 用的固定格式。飞控对格式很挑，
所以输出不做 alpha、不做调色板压缩，直接写 **24-bit BMP**。

## 目标格式

| 项目 | 固定值 |
|---|---|
| 分辨率 | **288 × 72** |
| 颜色深度 | **24-bit BMP** |
| 文件大小 | **62,262 字节** |
| 像素偏移 | 54 |
| 压缩 | 无压缩 |
| 颜色 | 只有 `(0,255,0)`、`(0,0,0)`、`(255,255,255)` |

`(0,255,0)` 是 OSD 工具认的透明色键；BMP 本身没有 alpha 通道。

## 工具

- 图形界面：`tools/osd_boot_logo.py`
- 命令行：

```powershell
.venv\Scripts\python.exe tools\osd_boot_logo.py 输入图.png -o 输出.bmp
```

可选参数：

```powershell
--mode fit      # 保持比例，留绿边（默认）
--mode fill     # 直接拉伸到 288×72
--mode cover    # 填满 288×72 并裁切
--background FF00FF   # 手动指定源背景色；默认从图片边框估计
--preview 预览.png    # 另存 4 倍放大预览
```

## 颜色清理

生成图/截图里的绿色通常不是单一颜色，边缘也有抗锯齿。工具不会用一个固定绿色值硬抠，
而是：

1. 从图片四周边框估计真实背景色；
2. 对每个像素分别计算“背景→白”和“背景→黑”的混合残差；
3. 取残差更小的那一个，得到前景和黑白分类；
4. 把前景/白色蒙版缩放到 288×72；
5. 强制量化成纯绿/纯黑/纯白三色。

这样即使背景是 `(1,203,90)` 到 `(2,205,92)` 的渐变，输出也不会带其他绿色。

## 检查

保存时会自动检查：

- 尺寸必须是 288×72；
- BMP 头必须是 24-bit、无压缩、像素偏移 54；
- 文件大小必须是 62,262 字节；
- 图像里不能出现第四种颜色。

如果任何一项不对，工具会直接报错，不会生成一个“看起来像 BMP 但飞控不认”的文件。

## 示例

Kepler V 图的输出在 `outputs/osd_logo/`：

- `kepler_v_boot_logo.bmp`：当前正式文件，fit，保持比例
- `kepler_v_boot_logo_preview.png`：4 倍预览
- `kepler_boot_logo*.bmp`、`kepler_v2_boot_logo.bmp`：早期文件名和模式对比，保留作历史记录

对应的 `*_preview.png` 是 4 倍放大预览，只用于查看，不要上传给飞控。
